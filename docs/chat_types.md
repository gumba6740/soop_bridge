# SOOP 채팅 타입별 parts 매핑

채팅 XML에서 루트의 자식 요소 하나가 `chats` 테이블의 한 행이 된다.
요소 이름은 `type` 컬럼에, 자식 요소의 **값**은 문서 순서대로 `parts` 배열에 들어간다.
시간 태그 `t`는 `time_offset` 컬럼으로 분리되므로 `parts`에는 없다.

- 인덱스는 **1부터** 센다. Postgres 배열 기준이다(`parts[1]`이 첫 번째). 파이썬 리스트로 받으면 0부터다.
- `?`는 의미를 아직 확인하지 못한 값이다.
- `challenge_mission`은 `parts[1]`(세부 타입)에 따라 구성이 다르다.
- 채팅 XML 버전 `1.0.0` 기준.
- 예시의 유저 ID, 닉네임, 채팅 메시지, 미션 제목, 영상 ID는 가짜 값이다.

## p, p2 비트 플래그

`chat`의 `p`(`parts[7]`), `p2`(`parts[8]`)와 `ogq`의 `sf`(`"p|p2"` 형태)는 숫자 하나가 아니라 **예/아니오 스위치 32개를 묶은 값**이다.
2진수로 바꿨을 때 각 비트가 켜져 있는지로 상태를 판단한다. 채팅을 친 **그 시점**의 상태다.

| 필드 | 비트 | 10진 값 | 뜻 | 확신도 |
|---|---:|---:|---|---|
| p | 2 | 4 | 스트리머 본인 | 확인 |
| p | 5 | 32 | 팬클럽 가입? (거의 모두 켜져 있음) | 추정 |
| p | 9 | 512 | ? | 미확인 |
| p | 14 | 16384 | 접속 환경? (p2 17번과 엇갈림, 같은 사람도 세션마다 다름) | 추정 |
| p | 15 | 32768 | 열혈팬 | 확인 |
| p | 16 | 65536 | ? (모두 켜져 있음) | 미확인 |
| p | 19 | 524288 | ? (같은 사람도 세션마다 다름) | 미확인 |
| p | 20 | 1048576 | ? | 미확인 |
| p | 28 | 268435456 | 구독 중 (`fw >= 0`과 항상 일치) | 확인 |
| p | 29 | 536870912 | 접속 환경? (14번과 함께 나옴) | 추정 |
| p | 31 | 2147483648 | ? | 미확인 |
| p2 | 15 | 32768 | ? (모두 켜져 있음) | 미확인 |
| p2 | 17 | 131072 | 접속 환경? (p 14번과 엇갈림) | 추정 |
| p2 | 18 | 262144 | 구독 등급 1 (베이직 추정, follow의 `stier=1`) | 등급 구분은 확인, 종류는 추정 |
| p2 | 19 | 524288 | 구독 등급 2 (플러스 추정, follow의 `stier=2`) | 등급 구분은 확인, 종류는 추정 |
| p2 | 25 | 33554432 | ? | 미확인 |

- 접속 환경으로 보이는 비트(p 14, 19, 29, p2 17)는 같은 사람의 `(2)` 세션끼리 달라진다. 유저 상태 분석에는 쓰지 않는다.
- 31번 비트가 있어서 `integer`로 바꾸면 넘칠 수 있다. SQL에서는 `bigint`로 바꿔서 비교한다.

```sql
-- 예: 채팅한 유저의 구독/열혈/등급 여부
SELECT parts[2] AS 유저,
       (parts[7]::bigint & (1::bigint << 28)) <> 0 AS 구독,
       (parts[7]::bigint & (1::bigint << 15)) <> 0 AS 열혈,
       CASE WHEN (parts[8]::bigint & (1::bigint << 19)) <> 0 THEN 2
            WHEN (parts[8]::bigint & (1::bigint << 18)) <> 0 THEN 1 END AS 구독_등급
FROM chats
WHERE type = 'chat';
```

## 할 일

- **팬클럽 미가입자 찾기.** 방송에서 팬이 아닌 사람을 발견하면 메모하고, 그 사람의 채팅이 있는 구간 XML로 `p` 5번 비트가 꺼져 있는지 확인한다. 풍선 1개만 보내도 팬이 되므로 대부분 켜져 있을 것으로 보인다.
- **서포터, 매니저 비트 찾기.** 해당하는 사람을 발견하면 같은 방법으로 확인한다. 후보는 뜻을 모르는 `p` 9, 20, 31번과 `p2` 25번이다.
- **구독 플러스/베이직 확정.** 플러스인 게 확실한 사람의 `p2`가 19번인지 확인한다.
- **`challenge_mission` 구성 전수 확인.** GIFT, SETTLE, NOTICE 외의 세부 타입이나 같은 세부 타입의 다른 길이가 있는지 DB 전체로 확인한다.
  ```sql
  SELECT parts[1] AS 세부_타입, array_length(parts, 1) AS 길이, count(*)
  FROM chats WHERE type = 'challenge_mission'
  GROUP BY 1, 2 ORDER BY 1, 2;
  ```
- **남은 `?` 필드.** 특히 `vballoon`의 `tn`, `st`, `d`(영상풍선 추정 검증)와 `ice`의 해제 값.
- **유저 ID의 `(n)` 접미사.** `dldudwns32(2)`처럼 세션마다 붙는다. 유저별로 집계할 때는 떼고 묶는다.
